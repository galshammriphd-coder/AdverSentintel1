# Implementation notes and deviations

1. **Quantities not specified in the paper.** The package sets: dropout 0.1, m = 8 learnable predicates, kappa = 0.5, anomaly threshold eta = 3.0, rule-weight learning rate mu = 0.05, rule evolution every 10 optimizer steps (streaming: every 10 windows), tau_s = 0.01. They are in `configs/sentinel_xlm.yaml`. The 15 initial rules in `rules/trust_rules.yaml` follow the three categories of Section 3.4.4 (behavioural consistency, anomaly response, relational trust); the predicates themselves are learned.
2. **Regularisation.** ||theta||^2 in Eq. (22) is divided by the number of parameters (`regularization_normalize: true`). The unnormalised sum exceeds the cross-entropy term by two orders of magnitude and prevents training. The symmetry term uses the fixed binary adjacency (edge weights 1.0), so it is logged but has no gradient.
3. **Batch size.** `batch_size` is the number of target windows (each with its T-1 history windows) per optimizer step.
4. **Metrics.** Node-window level; a node is predicted trustworthy if its trust score is at least 0.5; precision, recall and F1 are class-weighted; AUC uses the trust score. Early stopping uses validation AUC for SENTINEL-XLM and for all baselines.
5. **Graph.** Edges are directed from a source IP to a destination IP that is also a source node of the same window; node i aggregates from its communication partners. SMOTE is applied to the node feature vectors of the training windows only; synthetic nodes are isolated.
6. **SEM.** In static evaluation the SEM runs a Beta update over the T-step window with the model's own per-step trust as soft outcome, followed by the anomaly-triggered adaptation of Eq. (19). In the streaming evaluation the SEM keeps a persistent Beta belief per node and receives the observed outcome (label) of every window after it has been scored, and rule weights evolve by Eq. (20) every 10 windows. The No-SEM variant uses the trained trust scores unchanged.
7. **Baselines.** GCN-Trust, GAT-Security, GraphSAGE-Edge, EvolveGCN-Edge, DySAT-Trust, LLM-GNN and CausalNet are re-implemented in plain PyTorch from their descriptions (not the original code). TrustGNN and NeSy-Trust are the authors' own re-implementations; EdgeTrust-6G has no public code and is a temporal GAT with LSTM-based edge-weight evolution. CausalNet uses classical components in place of the quantum ones (learned DAG mask over node indices plus an MLP head). LLM-GNN embeds a text serialisation of the node features with GPT-2 small (the `hash` embedder is only for tests). Static models run on every snapshot of the window and average the node embeddings over the snapshots in which the node is present.
8. **Hyperparameter search.** `run_baseline_search.py` implements the grid of Section 4.1.3.1; the selected values are stored in `configs/baselines.yaml`.
9. **Efficiency.** `run_efficiency.py` and `run_scalability.py` measure the forward pass of one window sample (10 warm-up and 100 timed calls). Peak memory is `torch.cuda.max_memory_allocated` on a GPU and the process RSS increase on a CPU (noisy for small models). Table 15 values are analytical projections, not measurements on edge hardware: the script multiplies the measured FP32 server figures by the factors in `configs/edge_projection.yaml` and does not run quantization or pruning on a device.
10. **Explainability and LLM simulation.** The explainability script analyses a rating sheet with the columns `rater, sample_id, method, clarity, completeness, actionability`. The live simulation needs an OpenAI key (GPT-3.5-turbo agents) and a local Ollama server (llama3:8b agents); the `offline` mode is a deterministic stand-in used by the tests.
11. **Smoke outputs.** `results/smoke/` contains outputs of the one-epoch pipeline run on synthetic data. They verify that every script runs and carry no scientific meaning.
